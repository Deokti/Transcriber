# Системный дизайн — Transcriber

Черновик 1 · 16.09.2026 · опирается на `requirements.md` (черновик 2)

## 0. Чем дизайн отличается от требований

Требования отвечают на вопрос «что система делает». Дизайн — на три других:

1. Из каких частей она состоит?
2. Кто с кем разговаривает и в какую сторону?
3. Где лежат данные и кто ими владеет?

Признак хорошего дизайна простой: глядя на него, видно, **куда класть новую функцию**, и видно, **что сломается**, если вынуть кусок. Если на эти вопросы схема не отвечает — это картинка, а не дизайн.

---

## 1. Принципы

Пять правил, из которых выводится всё остальное. Когда дальше возникнет спор «как лучше», ответ ищем здесь.

- **П-1. Ядро не знает про интерфейс.** Ни печати на экран, ни вопросов пользователю, ни человеческих строк. Ядро возвращает данные, коды и события.
- **П-2. Зависимости идут в одну сторону:** интерфейс → ядро. Ядро не импортирует ничего из интерфейса, никогда. Это то, что позволяет иметь и окно, и командную строку без дублирования логики.
- **П-3. Сегменты — источник истины.** Всё остальное (txt, docx, субтитры) из них пересобирается и потому одноразово.
- **П-4. Долгая работа обязана** сообщать о прогрессе, отменяться и не блокировать интерфейс. Без исключений.
- **П-5. Платформенные различия живут в одном модуле.** Не размазаны условиями по всему коду.

Принцип П-1 выглядит теорией, пока не вспомнишь D-4: интерфейс переводится на два языка. Строка `sys.exit("Не найден ffmpeg")` в старом коде — это уже нарушение: она по-русски, она печатает, и она убивает процесс. Три греха в одной строке.

## 3. Ключевые объекты

### Segment — атом результата

```python
@dataclass
class Segment:
    start: float          # секунды
    end: float
    text: str
    no_speech_prob: float # вероятность, что это не речь
    avg_logprob: float    # уверенность модели
```

Последние два поля не нужны пользователю, но нужны нам: по ним ловятся залипания **до** того, как они попали в документ.

### Profile — все настройки задачи

Один объект вместо двадцати аргументов: язык, модель, устройство, тип вычислений, VAD, фильтры звука, обрезка, судьба промежуточного файла, форматы на выходе, вид оформления. Сохраняется в файл как пресет — «Лекция ru», «Интервью», «Английское видео».

Почему одним объектом: когда настроек двадцать, они начинают протекать в сигнатуры функций и в интерфейс по одной. Собранные вместе, они передаются насквозь и сериализуются одной строчкой.

### Job — задача

Файл + профиль + состояние (`в очереди / выполняется / готово / ошибка / отменена`) + прогресс по стадиям + список созданных артефактов + свой лог.

### Event — единственный способ ядра говорить наружу

```python
Event(kind=STAGE_STARTED, stage="prepare")
Event(kind=PROGRESS,      stage="transcribe", done=0.42, eta_s=1520)
Event(kind=STAGE_DONE,    stage="prepare", ms=61000)
Event(kind=WARNING,       code="REPEATS_FOUND", data={"share": 0.7, "at": 4200})
Event(kind=JOB_DONE,      artifacts=[...])
Event(kind=FAILED,        code="FFMPEG_MISSING")
```

Событие несёт **код и данные, а не готовую фразу**. Фразу собирает интерфейс из каталога перевода. Это и есть D-4 в работе: захотели добавить немецкий — правим один json, ядро не трогаем.

Единственное место, где ядро встречается с интерфейсом, — папка `app/bridge/`. Там живут объекты, у которых события ядра превращаются в свойства и сигналы, видимые из QML. Дальше в дело вступают привязки: изменилось свойство `progress` — полоса перерисовалась сама, без единой строки кода обновления. Это же и есть точка, которую придётся переписать, если однажды интерфейс заменят на веб или счёт уедет в отдельный процесс: всё остальное останется как есть.

## 4. Конвейер

| Стадия | Вход | Выход | Прогресс | Пропускается, когда |
|---|---|---|---|---|
| `probe` | исходный файл | длительность, дорожки, есть ли видео | нет | никогда |
| `prepare` | файл | WAV 16 кГц моно | да, по времени звука | попросили отдать исходник как есть |
| `transcribe` | WAV | `.segments.jsonl` | да, по позиции в аудио | цель — только аудио |
| `check` | jsonl | вердикт | нет | — |
| `export` | jsonl | txt / md / docx / srt | да, по числу форматов | цель — только аудио |
| `cleanup` | список артефактов | — | нет | попросили всё оставить |

Стадии одинаковы снаружи: получают `Job`, шлют события, умеют быть отменёнными между шагами. Поэтому сценарии из требований получаются не развилками в коде, а разным набором включённых стадий:

- **видео → документ**: все шесть;
- **только звук** (FR-8): `probe → prepare → cleanup`;
- **переэкспорт** (6.3): `export` в одиночку, на готовом jsonl.

## 5. Где крутится счёт (D-8)

```
     поток интерфейса                    рабочий поток
┌──────────────────────┐            ┌──────────────────────┐
│  окно PySide6        │  события   │  JobRunner           │
│  рисует, слушает     │ ◄───────── │  гоняет очередь      │
│  шлёт команды        │ ─────────► │  держит модель       │
└──────────────────────┘  старт/    └──────────┬───────────┘
                          отмена               │ дочерний процесс
                                          ┌────▼─────┐
                                          │  ffmpeg  │
                                          └──────────┘
```

Рабочий поток внутри того же процесса, что и окно. **Я меняю свою вчерашнюю рекомендацию** (была — отдельный процесс-исполнитель), и вот почему ваши ответы её перевесили:

- отпал второй движок на маке (D-2) — а он был бы внешней программой, и ради него процесс пришлось бы заводить всё равно;
- локальная нейронка ушла в «позже» (C-4) — второй тяжёлый потребитель памяти пока не появляется;
- D-1 говорит «сначала работающее из исходников» — а протокол общения между процессами это лишние сутки работы и вдвое более сложная отладка на старте.

Что мы теряем: если CUDA рухнет на уровне библиотеки (не исключение Python, а настоящий крах), приложение закроется вместе с очередью. Риск невысокий: у вас 16 ГБ VRAM, large-v3 занимает около трёх.

**Путь отступления оставлен нарочно.** Интерфейс общается только с `JobRunner` — командами внутрь и событиями наружу. Если однажды переезд в отдельный процесс понадобится, меняется одна реализация `JobRunner`: команды превращаются в строки JSON в трубу, события — в строки обратно. Окно об этом не узнает. Именно ради этого между ними и стоит фасад, а не прямые вызовы.

Командная строка воркер не использует вовсе: она гоняет конвейер прямо в себе и печатает те же события, только словами.


### Рядом с исходником (или в выбранной папке)

```
lecture.mkv                 исходник
lecture.segments.jsonl      источник истины (П-3)
lecture.txt / .docx / .md   документы
lecture.srt                 субтитры
```

Строка `jsonl` — один сегмент:

```json
{"start": 754.12, "end": 759.98, "text": "…", "no_speech_prob": 0.01, "avg_logprob": -0.28}
```

Формат выбран нарочно построчным: пишется по ходу распознавания, читается кусками, не портится при обрыве — оборванной окажется последняя строка, остальные целы. Отсюда и D-7: прервалось на 70-й минуте — 70 минут работы лежат на диске.

## 7. Зависимости и первый запуск

`deps/catalog.json` — единственное место, где записано, что откуда качать: для каждой пары «ОС + архитектура» адрес, размер, контрольная сумма. Обновить ссылку на новую сборку ffmpeg = поправить json.

| Что | Откуда | Размер |
|---|---|---|
| ffmpeg + ffprobe | официальные статические сборки под каждую ОС | ~80–120 МБ |
| модели Whisper | HuggingFace, формат CTranslate2 | от 75 МБ (tiny) до ~3 ГБ (large-v3) |

Правила: качаем по требованию, проверяем контрольную сумму, умеем докачать прерванное, при отсутствии сети говорим об этом внятно (`code=NETWORK_UNAVAILABLE`), а не роняем задачу на середине.

Экран **Хранилище**: что скачано, сколько весит, удалить по одному или всё. Экран **Диагностика**: ffmpeg найден, CUDA готова, столько-то моделей, столько-то свободного места. Оба закрывают FR-25 и FR-27 и экономят будущие вечера отладки.

## 8. Платформы

| | Устройство | Тип вычислений | Ориентир скорости на large-v3 | Что показываем |
|---|---|---|---|---|
| Windows + NVIDIA | GPU | float16 | ~2.5× быстрее реального времени | всё доступно |
| Linux + NVIDIA | GPU | float16 | то же | всё доступно |
| Любая без GPU | CPU | int8 | заметно медленнее реального времени | предупреждение о времени |
| macOS | только CPU | int8 | около реального времени и медленнее | GPU выключен + пояснение + совет взять модель полегче |

Модуль `platform.py` — единственное место, которое об этом знает: он определяет доступные устройства, подбирает разумные значения по умолчанию и отдаёт интерфейсу список того, что можно выбрать, с причинами для недоступного. Ни в одной стадии не должно быть проверки «а мы случайно не на маке».

Внутри него же живёт наследник `cuda_setup.py` — подгрузка библиотек CUDA на Windows. Это самая хрупкая часть системы: CTranslate2 загружает cuBLAS и cuDNN в обход обычного механизма поиска, и именно здесь всё ломалось при первой настройке. Код рабочий, но он должен уметь объяснять, чего не хватает, кодом ошибки — а не строкой по-русски.

## 9. Языки интерфейса

Каталог — обычный json:

```json
{ "stage.prepare": "Подготовка звука",
  "error.FFMPEG_MISSING": "Не найден ffmpeg. Скачать сейчас?" }
```

Интерфейс зовёт `t("stage.prepare")`. Ядро про эти строки не знает вообще. Добавить язык = положить ещё один json. Проверка на забытые ключи делается простым скриптом: сравнить наборы ключей во всех каталогах.

## 10. Ошибки

Ядро не бросает голые исключения наружу и не печатает текст. Оно отдаёт код, данные и, где уместно, предложение что сделать:

| Код | Когда | Что предлагаем |
|---|---|---|
| `FFMPEG_MISSING` | нет бинарника | скачать (FR-24) |
| `MODEL_MISSING` | модель не скачана | скачать, показав размер |
| `CUDA_UNAVAILABLE` | нет библиотек или карты | переключиться на CPU с предупреждением о времени |
| `NO_AUDIO_TRACK` | в файле нет звука | пропустить файл |
| `DISK_FULL` | не хватает места | сколько нужно и сколько есть |
| `CANCELLED` | пользователь отменил | убрать за собой |

## 12. План этапов

Каждый этап заканчивается чем-то, что можно запустить и проверить. Это важнее, чем кажется: иначе через две недели будет красивая архитектура, которая ни разу не распознала ни одной лекции.

| Этап | Что делаем | Как проверяем |
|---|---|---|
| **M1** ✔ | Скелет: `platform`, `profile`, `job`, `events`, перенос кода, конвейер, CLI поверх нового ядра | сделано 16.09.2026: `python -m cli` проходит все шесть стадий, вердикт по качеству на месте |
| **M2** | `JobRunner`, события, очередь, отмена | ставим три файла, отменяем второй, третий считается |
| **M3** | Окно: выбор файла, настройки, стадии, прогресс, результат | проходим сценарий 6.1 мышкой, не открывая консоль |
| **M4** | `deps`: скачивание ffmpeg и моделей, Хранилище, Диагностика | на чистой машине без ffmpeg приложение доводит до результата само |
| **M5** | Экспорт: txt, md, docx, srt + два вида оформления + переэкспорт | из одного jsonl получаем четыре файла за секунду |
| **M6** | Переводы интерфейса, проверка на macOS | то же самое на маке, по-английски |
| **M7** | Сборка установщика (D-1) | человек без Python запускает и работает |

Дальше, вне этого плана: локальная нейронка (C-4), диаризация, возобновление прерванного.

## 13. Чего сознательно не делаем сейчас

Список не менее важен, чем сам дизайн — он защищает от расползания:

- **второго движка распознавания** (whisper.cpp с Metal) — место оставлено в `core/asr/base.py`;
- **отдельного процесса-исполнителя** — место оставлено в фасаде `JobRunner` (§5);
- **постобработки через LLM** — место оставлено: это ещё одна стадия конвейера между `check` и `export`;
- **возобновления прерванного** — формат jsonl это позволит, когда понадобится;
- **диаризации** (кто говорит) — тяжёлая зависимость, пока не нужна;
- **базы данных истории** — хватит того же jsonl.

Во всех шести случаях мы не «делаем задел», а просто не строим стену там, где завтра может понадобиться дверь. Разница принципиальная: задел стоит времени сейчас, а незакрытая дверь — ничего.
