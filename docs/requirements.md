# Требования — Transcriber

Черновик 2 · 16.09.2026

## 0. Как устроен документ

Требования делят на три вида, и смешивать их — главная ошибка новичка:

- **ФТ (функциональные)** — *что система делает*. «Пользователь может выбрать язык».
- **НФТ (нефункциональные)** — *какой она должна быть*. Скорость, платформы, размер, надёжность. Их забывают, а потом оказывается, что архитектура их не держит.
- **Ограничения** — *что физически нельзя* или что уже задано извне. Именно они рубят половину вариантов архитектуры, поэтому выписаны отдельно.

У каждого пункта номер. Дальше в коде, задачах и спорах ссылаемся на номер.

Пометки: **[+]** — добавлено при разборе, не было в исходном списке. **[позже]** — согласовано, но не в первой версии.

---

## 1. Зачем это

Настольное приложение: видео или аудио → текст. В одном запуске объединяет ffmpeg (подготовка звука) и faster-whisper (распознавание), даёт понятный выбор опций и оформленный документ на выходе.

Почему не WhisperDesktop: там не выключается `condition_on_previous_text` и нет управляемого VAD. Из-за этого модель залипает — повторяет одну фразу («[Стук в дверь]») часами. Управляемость этих двух параметров и есть причина существования проекта; всё остальное — удобство вокруг.

## 2. Словарь

Договоримся о словах сразу, иначе через месяц запутаемся:

- **Распознавание (ASR)** — речь → текст на том же языке. Это то, что делает Whisper.
- **Перевод** — текст с одного языка на другой. В проекте этого нет и пока не планируется.
- **Сегмент** — кусок речи с тайм-кодами, единица выдачи Whisper (обычно 5–6 секунд).
- **Стадия** — шаг конвейера: подготовка звука, распознавание, проверка, выдача, очистка.
- **Артефакт** — любой файл, созданный по пути: промежуточный WAV, сегменты, txt, docx.

## 3. Функциональные требования

### 3.1 Ввод

- **FR-1** Принимать видео и аудио популярных форматов (mp4, mkv, mov, avi, webm, m4a, mp3, wav, ogg, opus, flac, aac…). Определять тип по содержимому, а не по расширению.
- **FR-2** Если в файле несколько аудиодорожек — показать список (кодек, число каналов, язык, название) и дать выбрать нужную.
- **FR-3 [+]** Очередь: поставить несколько файлов подряд. Модель грузится один раз на всю очередь (на large-v3 это 70 секунд, которые иначе платятся за каждый файл). Ошибка на одном файле не роняет остальные. Решение **D-6**.

### 3.2 Подготовка звука (ffmpeg)

- **FR-4** Шумоподавление — включаемо.
- **FR-5** Выравнивание громкости — включаемо.
- **FR-6** Обрезка начала и конца по тайм-кодам.
- **FR-7** Результат подготовки — WAV 16 кГц моно: ровно то, во что Whisper всё равно конвертирует внутри, так что лишней потери качества нет.
- **FR-8** Сценарий «нужно только аудио»: остановиться после этой стадии и отдать звуковой файл, не запуская распознавание.

### 3.3 Распознавание

- **FR-9** Язык выбирает пользователь — явно, из списка языков Whisper. Автоопределение не является основным путём: угадывание даёт тихие ошибки, которые всплывают уже в готовом тексте. Решение **D-4**.
- **FR-10** Выбор модели (tiny … large-v3, турбо-вариант). Для каждой видно: размер файла, примерная скорость, качество, скачана или нет.
- **FR-11** Выбор устройства: GPU или CPU, плюс тип вычислений. Правила по платформам — **D-2**:
  - Windows и Linux с видеокартой NVIDIA: доступны оба варианта, по умолчанию GPU;
  - GPU недоступна или сломана — честное сообщение и откат на CPU, а не падение;
  - **macOS: пункт GPU виден, но выключен, и рядом написано почему** — «на Mac ускорение недоступно: движок распознавания умеет работать с видеокартами только через CUDA, а её на Mac не существует». Пользователь не должен гадать, почему кнопка серая.
- **FR-12** Защита от залипаний включена по умолчанию: `condition_on_previous_text=False` + VAD. Отключается только осознанно, с предупреждением.
- **FR-13** Прогресс в процентах с оценкой оставшегося времени.
- **FR-14 [+]** Отмена в любой момент, без зависшего окна и без мусора на диске.
- **FR-15 [+]** На macOS по умолчанию предлагается модель полегче (турбо или medium), с пояснением. На CPU large-v3 считает три часа лекции дольше трёх часов — человек должен узнать это до запуска, а не через час ожидания.

### 3.4 Проверка качества

- **FR-16 [+]** После распознавания — автоматическая проверка транскрипта: серии одинаковых строк, повторы-циклы, дыры в таймлайне. Пользователю показывается вердикт: «ЧИСТО» / «мелкие повторы» / «ЕСТЬ ЗАЛИПАНИЯ» с указанием, где именно.

  *В исходном сценарии этого шага не было, но именно от этой боли проект и начался. Код проверки уже написан и на реальных трёх часах отработал.*

### 3.5 Выдача документа

- **FR-17** Форматы: **txt**, **md**, **docx**. Формат `.doc` исключён — решение **D-3**, обоснование в C-2. **[+]** Субтитры srt/vtt — дёшево и полезно для видео.
- **FR-18** Два вида оформления в первой версии:
  1. как есть, с тайм-кодами;
  2. чистый связный текст без тайм-кодов, собранный в абзацы.

  Третий (через локальную нейронку) — см. 3.6.
- **FR-19 [+]** Сегменты всегда сохраняются в машинный файл (`.jsonl`) рядом с результатом. Из него любой формат пересобирается за секунду — без повторного распознавания. Иначе смена формата означает заново 80 минут счёта.
- **FR-20** Выбор папки для результата: рядом с исходником или в заданную.

### 3.6 Постобработка локальной моделью **[позже]**

Согласовано как направление, но не входит в первую версию. Требования фиксируются, чтобы архитектура оставила для этого место.

- **FR-21** Опционально прогнать готовый текст через локальную LLM, чтобы получить оформленный документ: заголовки, разделы, списки, расставленная пунктуация.
- **FR-22** Жёсткое правило: модель **структурирует, но не переписывает**. Оригинальный транскрипт сохраняется всегда, рядом.
- **FR-23** Приложение не тащит LLM внутрь себя, а обращается к уже стоящему на машине локальному сервису.

### 3.7 Зависимости: ffmpeg и модели

- **FR-24** Ни ffmpeg, ни модели не входят в дистрибутив. Скачиваются при первом использовании, один раз.
- **FR-25** Всё скачанное лежит в одной папке данных приложения — видно, что скачано и сколько весит, есть кнопка «удалить». Расположение папки — решение **D-5**.
- **FR-26** Прогресс скачивания, проверка целостности, продолжение прерванной загрузки, понятная ошибка при отсутствии сети.
- **FR-27 [+]** Панель диагностики: найден ли ffmpeg, готова ли CUDA, какие модели на месте, сколько свободно на диске. Один экран, снимающий 90% вопросов «почему не работает».

### 3.8 Ход работы и промежуточные файлы

- **FR-28** Видимые стадии с уведомлением о завершении каждой: «этап 1 закончен, приступаем ко второму».
- **FR-29** Промежуточный WAV: удалить / оставить / перенести рядом с исходником. Выбор делается **до** запуска, чтобы не пришлось сидеть у экрана 80 минут ради одного вопроса в конце.
- **FR-30** Очистка артефактов — отдельная видимая стадия, а не молчаливое действие.

## 4. Нефункциональные требования

- **NFR-1 Платформы.** Windows и macOS — с первого дня, Linux — попутно (по устройству он ближе к Windows, чем к маку). Решение **D-1**.
- **NFR-2 Приватность.** Всё считается локально. В сеть уходят только скачивания ffmpeg и моделей. Ни одна секунда звука не покидает машину — для лекций, созвонов и интервью это главное преимущество перед онлайн-сервисами.
- **NFR-3 Размер.** В дистрибутив не входят ни ffmpeg (~100 МБ), ни модели (до ~3 ГБ) — они докачиваются по требованию. Сама программа со всем, что нужно для запуска, укладывается в 80–150 МБ (уточнено после D-9: столько занимает связка Python + Qt).
- **NFR-4 Устойчивость.** Интерфейс не замирает во время счёта. Сбой распознавания не уносит очередь и не оставляет мусор на диске.
- **NFR-5 Языки интерфейса.** Интерфейс переводится: русский и английский как минимум, языков немного. Решение **D-4**. Следствие для архитектуры жёсткое: **в ядре не должно остаться ни одной человеческой строки** — ядро возвращает коды событий и ошибок, а слова к ним подбирает интерфейс.
- **NFR-6 Скорость.** Ориентир, измеренный на вашей машине (RTX 5070 Ti, 16 ГБ): large-v3 считает примерно в 2.5 раза быстрее реального времени — 3 часа аудио за 80 минут. Модель грузится 70 секунд. На macOS ориентир другой, см. C-1.

## 5. Ограничения и конфликты

Самая полезная часть документа: здесь написано, где требования спорят с реальностью.

### C-1. macOS и GPU

CUDA существует только для видеокарт NVIDIA, то есть Windows и Linux. На Mac её нет. faster-whisper построен на CTranslate2, а тот на маке умеет **только CPU** — ни Metal, ни Neural Engine он не использует.

> **Решение D-2:** на macOS работаем на CPU. Пункт «GPU» в интерфейсе виден, но выключен, с пояснением причины (FR-11). Дополнительно на маке по умолчанию предлагается модель полегче (FR-15), потому что large-v3 на процессоре медленнее реального времени.
>
> Следствие: сменный движок распознавания (whisper.cpp с Metal) **не строим**. Модуль `asr` остаётся с узкой границей, чтобы второй движок можно было добавить, если однажды скорость на маке станет проблемой — но пустой абстракции «на всякий случай» не делаем.

### C-2. Формат .doc

`.doc` — закрытый двоичный формат Word 97–2003. Ни одна библиотека Python его честно не пишет: то, что выдают за «.doc», обычно либо переименованный docx, либо HTML внутри.

> **Решение D-3:** только docx. Word открывает его начиная с версии 2007, то есть последние 18 лет. Из требований `.doc` вычеркнут.

### C-3. Где лежат скачанные данные

Требование FR-25 звучало как «всё внутри папки приложения, чтобы при удалении удалялись и модели». Идея верная, но у операционных систем на этот счёт есть правила:

- **macOS** — приложение лежит в подписанном бандле `.app`, который система защищает от записи. Данные полагается класть в `~/Library/Application Support/<имя>`.
- **Windows** — если приложение стоит в `Program Files`, запись туда требует прав администратора. Данные полагается класть в `%LOCALAPPDATA%\<имя>`.
- **Linux** — есть стандарт XDG: данные в `~/.local/share/<имя>`, кеш в `~/.cache/<имя>`.

Эти правила существуют не из вредности: они позволяют нескольким пользователям одного компьютера иметь свои настройки, а резервному копированию — понимать, что сохранять.

> **Решение D-5:** два режима.
>
> 1. **Обычный** (по умолчанию): данные в стандартной папке своей ОС из списка выше.
> 2. **Портативный**: если рядом с приложением лежит файл-маркер `portable`, всё складывается в папку `data/` рядом с ним. Тогда «удалил папку — удалилось всё», как вы и хотели, и приложение можно носить на флешке.
>
> В обоих режимах внутри приложения есть экран «Хранилище»: что скачано, сколько весит, кнопка удалить — по отдельности и всё сразу. Это честнее, чем надеяться, что пользователь найдёт папку руками: на macOS полного «перетащил .app в корзину — исчезли все 3 ГБ» не бывает ни у одной программы.

### C-4. Локальная нейронка на трёх часах текста **[позже]**

Три часа речи — это 50–60 тысяч токенов, в один запрос локальной модели не помещается. Нужна нарезка с перекрытием, обработка по частям и сборка, то есть постобработка сама по себе небольшой конвейер. На 16 ГБ VRAM реально крутить модель 14B в 4-битном кванте, время работы — десятки минут. К этому вернёмся после первой рабочей версии.

## 6. Сценарии

### 6.1 Основной: видео → документ

1. Выбрать видео.
2. Выбрать язык из списка.
3. Выбрать обработку звука: шумоподавление, выравнивание громкости, обрезка начала и конца.
4. Если дорожек несколько — выбрать нужную.
5. Решить судьбу промежуточного файла: удалить / оставить / перенести.
6. Выбрать формат документа: docx.
7. Выбрать оформление: с тайм-кодами или чистый текст.
8. Запуск. Видны стадии:
   - **1. Подготовка звука** — проценты, по окончании «этап 1 завершён»;
   - **2. Распознавание** — проценты и оставшееся время;
   - **3. Проверка** — вердикт по залипаниям **[+]**;
   - **4. Выдача документа**;
   - **5. Очистка** — удаление промежуточного WAV, освобождение памяти.
9. Готово: показать, где лежат файлы, и дать открыть папку.

*Отличие от исходной версии: судьба промежуточного файла выбирается до запуска. Тогда можно уйти и вернуться к готовому результату — иначе процесс встанет посреди ночи в ожидании ответа.*

### 6.2 Только звук

Шаги 1–5, стоп после подготовки. На выходе — очищенный аудиофайл.

### 6.3 Переэкспорт готового

Взять существующий `.jsonl`, выбрать другой формат или другое оформление, получить документ за секунду. Без распознавания.

### 6.4 Первый запуск

Приложение видит, что нет ни ffmpeg, ни моделей. Показывает, что нужно скачать и сколько это весит. Пользователь соглашается, видит прогресс. Дальше всё локально.

## 7. Решения

Принято 16.09.2026:

| № | Решение | Следствие для архитектуры |
|---|---|---|
| **D-1** | Сначала запуск из исходников, сборка установщика — отдельным этапом позже | Код сразу пишется «упаковываемым»: никаких абсолютных путей, ресурсы через штатный механизм |
| **D-2** | На macOS только CPU, GPU-пункт выключен с пояснением; второй движок не строим | Один движок (faster-whisper) на всех платформах, модуль `asr` с узкой границей |
| **D-3** | Документы: только docx (плюс txt, md, srt) | Одна библиотека, ноль внешних зависимостей |
| **D-4** | Интерфейс переводится (ru + en); язык распознавания пользователь выбирает явно | В ядре нет человеческих строк: только коды событий и ошибок |
| **D-5** | Данные — в стандартной папке ОС, плюс портативный режим по файлу-маркеру | Модуль `platform` — единственное место, знающее про пути |
| **D-6** | Очередь из нескольких файлов — закладывается сразу | Модель данных оперирует списком задач, а не одной |
| **D-7** | При обрыве ничего не теряется (сегменты пишутся по ходу), но автоматического возобновления в первой версии нет | Формат `.jsonl` уже позволяет дописать возобновление позже |
| **D-8** | Счёт идёт в рабочем потоке за фасадом, а не в отдельном процессе | Обоснование и путь отступления — в `architecture.md` |
| **D-9** | Язык — Python, интерфейс — PySide6 (Qt) | Одна кодовая база, один процесс, одна сборка. Любой другой язык означал бы отказ от faster-whisper (он существует только для Python) плюс второй язык сверху, потому что тяжёлая часть всё равно осталась бы питоновской |
| **D-10** | Интерфейс на Qt Quick (QML), не на Qt Widgets | Декларативное описание с выражениями на JavaScript, отрисовка на видеокарте, анимации и тени дёшевы. Разбор — в [ADR-0002](adr/0002-qml-vs-widgets-vs-web.md) |
| **D-11** | Стиль собственный, приложение не подражает родному виду каждой ОС | Один набор макетов на три системы вместо трёх. Цена: нигде не выглядит «как родное» — как Telegram, DaVinci Resolve, Cura |
